## Concepts to understand first

1. **Spring Boot auto-configuration.** Starters on the classpath trigger auto-config
   classes. `spring-boot-starter-data-jpa` activates `DataSourceAutoConfiguration`, which
   *insists* on a datasource when the context starts. That is why `contextLoads()` fails —
   no datasource, no context, no pass. The error `Failed to determine a suitable driver
   class` is this, **not** a Java-version problem.
2. **Gradle Java toolchains.** `languageVersion` selects the JDK, independent of the shell's
   JDK. 25 was set; 21 is installed → retarget to 21.
3. **Docker Compose basics.** `service`, `ports`, `environment`, `volumes`, `healthcheck`.
4. **Flyway.** Versioned SQL migrations in `db/migration/`, run at startup. On PG 17 needs
   `flyway-database-postgresql`, not just `flyway-core`.
5. **Testcontainers.** Starts a real Postgres in Docker for tests; `@ServiceConnection`
   (Spring Boot 3.1+) auto-wires its connection details.

**Framing:** two levers fix an auto-config failure — change *what's on the classpath*
(dependencies), or change *what the context needs* (profiles/config/test).
